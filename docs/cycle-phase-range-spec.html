Overview

This document specifies how Ritu computes and displays menstrual cycle phases (Menstrual, Follicular, Ovulatory, Luteal) across all user classifications (Regular, Variable, Unpredictable), including the short-cycle edge case and the hero card's update behavior. It is the single source of truth for this logic; changes to phase calculation or hero card display behavior should be made here first.

1. Base Definitions

Two values are treated as fixed anchors. All other ranges are derived from them.

AnchorDefinition
MenstrualDay 1 of the cycle is the day a period was logged. This is observed data, not a calculated estimate, for every classification.
LutealThe final 14 days of the cycle, counted backward from the day the next period starts. This is treated as the most biologically stable phase and is never shortened except under the Tier C fallback (Section 4.3).

No other value is required as an input to this system besides these two anchors, P, and C (defined below).

2. Core Formula

Inputs

SymbolDefinition
PPeriod duration, in days
CTotal cycle length, in days (period start to next period start)

Derivation

Menstrual   = day 1     to day P
Follicular  = day P+1   to day C-17
Ovulatory   = day C-16  to day C-14
Luteal      = day C-13  to day C
PhaseBasis
MenstrualFixed anchor: day 1 to P, taken directly from logged data
LutealFixed anchor: the final 14 days, counted backward from day C
OvulatoryA fixed 3-day window immediately preceding Luteal
FollicularThe remainder between the end of Menstrual and the start of Ovulatory. This is the only phase whose length varies with cycle length.
P and C are the only two inputs to this system. Menstrual and Luteal are fixed anchors; Ovulatory is offset a fixed distance from Luteal; Follicular absorbs whatever length remains. No phase boundary is hardcoded to a specific day count.

4. Edge Case: Insufficient Cycle Length Resolved

4.1 Failure mode

For a sufficiently short cycle relative to period length, the standard formula produces an invalid (negative-length) Follicular range.

Example: P=5, C=21.

PhaseFormulaResult
Menstrual1 to PDay 1–5
FollicularP+1 to C-17Day 6 to Day 4 — invalid
OvulatoryC-16 to C-14Day 5–7
LutealC-13 to CDay 8–21
Cause: Ovulatory (3 days) + Luteal (14 days) + a 5-day period already total 22 days, one more than the 21-day cycle. There is no remaining length for Follicular, and the unmodified formula produces overlapping, invalid ranges.

4.2 Resolution strategy

Priority order when cycle length is constrained: preserve Luteal → compress Ovulatory → drop Follicular.

  • Luteal is the anchor defined as most biologically stable (Section 1) and is the last phase to be reduced.
  • Ovulatory is a fixed 3-day convention rather than a hard biological boundary, and is the least costly phase to compress.
  • Follicular is defined as "remaining length" (Section 2); when no length remains, it does not appear. This follows directly from its definition rather than requiring a special case.

Step 1 — compute available length after the period:

available = C - P

Step 2 — apply tier:

TierConditionBehavior
A — Normalavailable >= 17Standard formula (Section 2). Follicular = available - 17, Ovulatory = 3, Luteal = 14.
B — Compressed15 <= available < 17Follicular omitted for this cycle. Ovulatory = available - 14 (1–2 days). Luteal remains fixed at 14.
C — Irregularavailable < 15No phase math is attempted; even a 1-day Ovulatory and 14-day Luteal do not fit. Handled as Section 4.3.

Worked resolution, P=5, C=21: available = 16 → Tier B → Ovulatory = 2 days.

PhaseRange
MenstrualDay 1–5
OvulatoryDay 6–7
LutealDay 8–21
Total21 days, no overlap

Follicular is absent from this cycle's output; it is not rendered as a zero-width segment.

4.3 Additional condition

If C <= P (period duration equal to or exceeding total cycle length — typically a logging error), route directly to Tier C regardless of the computed available value.

4.4 Hero card behavior by tier

TierHero card behavior
AStandard 4-segment strip (Section 8), unmodified.
B3-segment strip: Menstrual → Ovulatory → Luteal. Follicular is removed from the strip, not collapsed to near-zero width. On the day following the period, the label transitions directly from "Menstrual" to "Ovulatory phase." On first occurrence for a given user, display a one-time explanatory message: "Your cycle this time is on the shorter side — the Follicular window was too brief to show separately."
CNo phase strip is rendered. Reuse the Unpredictable-classification neutral card component (Menstrual when logged, plain neutral card otherwise), with cycle-specific copy rather than classification copy: "This cycle looks unusually short — we're not showing phase estimates for it." This also signals to the user that the logged dates may warrant review.

4.5 Rationale: Tier B is not merged into the Unpredictable pattern

Unpredictable is a user-level classification derived from six cycles of observed variance; it represents insufficient confidence in a user's data to attempt phase calculation at all. Tier B is a single-cycle condition for an otherwise Regular or Variable user, in which Ovulatory and Luteal remain valid, non-overlapping calculated ranges — only Follicular lacks sufficient length. Substituting the Unpredictable neutral card in this case would discard valid ovulation-window data for any user with a single shorter-than-typical cycle, which is a common occurrence, not a rare one.

5. Parameter Selection by Classification

ClassificationValue used for CDisplay treatment
RegularThe user's personal average cycle length (single stable value)Exact ranges — e.g., "Day 14 · Follicular phase"
VariableThe midpoint of the user's observed range (see Section 6)Identical formula to Regular, displayed as an estimate — e.g., "probably Follicular," denoted with ~
UnpredictableNot applicable — no calculation is attemptedOnly Menstrual (logged) is shown; all other days display a neutral card

Regular and Variable classifications use an identical calculation. The only difference is the confidence level associated with the input value for C, reflected in copy and UI treatment — not in the underlying formula.

6. Variable Classification: Range Calculation

6.1 Data window

The sample size used for both classification and range calculation follows a single shared, incrementally growing window:

Cycles loggedData used
1–2Unclassified — insufficient data
3All 3 cycles
4All 4 cycles
5All 5 cycles
6+Most recent 6 cycles, rolling (cycle 7 displaces cycle 1, etc.)

This window is identical to the one used by the classification engine (minimum 3 cycles; mean absolute deviation computed over the most recent 6), so the Variable range is always derived from the same data that produced the classification, rather than an independently defined sample.

6.2 Midpoint definition

The midpoint used for C is not a median of the full sample. It is calculated from only the shortest and longest values in the window:

midpoint = (shortest + longest) / 2

Values between the extremes (e.g., a middle value in a 3-cycle sample) contribute to the classification's mean-absolute-deviation calculation but are not inputs to the midpoint or range calculations described in Sections 6.3–6.4.

6.3 Rounding

shortest + longest is frequently odd (e.g., 24 + 33 = 57 → 28.5). Round half up to the nearest whole day (28.5 → 29). This rounding rule is a defined requirement, not an implementation detail left open to interpretation.

Note: With smaller sample sizes (e.g., 3 cycles), a single atypical cycle has proportionally greater influence on the computed midpoint and range than it would with a full 6-cycle sample. This is expected behavior; the existing estimate-hedging treatment (tilde, "probably") is designed to account for it. The range is expected to narrow as more cycles are logged.

6.4 Calculation methods

Two calculations are performed for a Variable user. They answer different questions and are not interchangeable; both run for every applicable cycle.

Method 1 — Point estimate (displayed value)

Uses the midpoint of the observed range as C, applied to the standard formula (Section 2). This is the only output of this section shown to the user.

Example: shortest = 24, longest = 33 → midpoint ≈ 29 (P=5):

PhaseRange
MenstrualDay 1–5
FollicularDay 6–12
OvulatoryDay 13–15
LutealDay 16–29

Method 2 — Range of possibility (uncertainty measurement, not displayed)

Substitutes the shortest and longest observed cycle lengths independently into the Ovulatory and Luteal-start expressions from Section 2 (Ovulatory = day C-16 to C-14, Luteal start = day C-13). Note that P does not appear in either expression and plays no role in this calculation.

If C = 24 (shortest): Ovulatory start = 24−16 = 8; Ovulatory end = 24−14 = 10 → Day 8–10. Luteal start = 24−13 = 11.
If C = 33 (longest): Ovulatory start = 33−16 = 17; Ovulatory end = 33−14 = 19 → Day 17–19. Luteal start = 33−13 = 20.

PhaseIf short (C=24)If long (C=33)
OvulatoryDay 8–10Day 17–19
Luteal startDay 11Day 20

The output used from this method is the width of the range: latest possible end (19) minus earliest possible start (8) = an 11-day uncertainty window. This value is the basis for classifying Ovulatory as the least reliable phase estimate for Variable users. Neither "Day 8–10" nor "Day 17–19" is displayed to the user as a phase estimate; only Method 1's output (e.g., "~Day 13–15") is shown. Method 2 exists solely to calibrate the degree of hedging applied to the displayed estimate.

Future extension: if a detail view explaining the estimate's uncertainty is implemented, Method 2's range (e.g., "Ovulatory could fall anywhere between day 8 and day 19") is appropriate content for it, as supplementary detail beneath the Method 1 value — not as a replacement for it.

7. Hero Card Update Triggers

TriggerBehavior
A new day beginsThe day count advances by one. If this crosses a phase boundary, the hero card updates its color and label.
A new period is loggedThe day count resets to 1 immediately upon logging, independent of calendar day. The hero card transitions to Menstrual at that moment.
Classification changesA distinct, lower-frequency event that determines whether phase-based display applies at all. Initial classification (Unclassified → Regular/Variable/Unpredictable) or reclassification can change the entire hero card treatment — e.g., from a dimmed "estimated" state to full confidence, or from a phase card to the Unpredictable neutral card.
