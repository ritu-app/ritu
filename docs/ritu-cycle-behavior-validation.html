Ritu validation guide

Cycle behavior, in one plain-language spec

This page combines the period-boundary, hero-card confidence, cycle-classification, and phase-range specs into one document that product, design, QA, and engineering can use to validate the app behavior.

The app should feel honest, not overconfident

  • Use confirmed logs when they exist. Use estimates only when the app has to, and make that uncertainty visible.
  • Do not punish silence. A missed day is not the same as explicitly choosing None.
  • Keep the home hero Neutral until the app has enough data and has observed one complete cycle live.
  • Classify cycles by recent personal consistency, not by whether they match a textbook 28-day cycle.

1. Mental Model

Ritu is tracking two related things: period episodes and cycle starts. A period episode begins when flow is logged. A cycle length is measured from one period start to the next period start.

The app may know a date from live logging or from memory. Both can be used for classification math, but only live-logged dates let the hero card look fully confident.

Period

One bleeding episode. It has a start date and, when known, an end date. Bleed days are inclusive from start to end.

Cycle

The day range from one period start to the next. Four period starts create three completed cycles.

Logged date

Entered live through daily logging when the event happens. This is high-confidence data.

Manual date

Entered from memory through onboarding, Settings, or a recovery flow. It counts, but the display should be more cautious.

2. Period Boundaries

The app must avoid splitting one real period into two fake periods just because the user had a short spotting gap. It also must avoid treating app inactivity as proof that bleeding stopped.

Rule Expected behavior Validation signal
Flow starts a period Any explicit flow value other than None starts or continues a period episode. The current cycle day resets to Day 1 when a new period start is logged.
Two explicit None days close it A period does not close on the first None. It closes only after 2 consecutive explicit None days. A one-day gap followed by flow remains the same period.
Silence is not None A day with no app activity does not increment the None counter. Skipped days alone never close a period.
Day 10 safety cap If the period is still open by day 10 from its start, the app closes it automatically. Irregular spotting cannot keep one period open forever.
Assumed duration fallback If the user logs Day 1 and then goes silent, the hero continues using an estimated period length. The hero does not freeze, but later confirmation can correct the true end date.

Home nudge behavior

After the assumed period boundary has passed and the user has not logged new flow or explicit None, Home shows a dismissible card: Still on your period?

User actionResult
Still goingDismiss the card for the day. Continue with estimated behavior.
DismissSame as Still going. Do not repeatedly ask the same day.
It endedOpen a short confirm screen: Today, Yesterday, 2 days ago, or Pick a different date. The selected date becomes the true period end.

3. Hero Card Confidence

The hero card starts cautious and becomes more specific only when two conditions are both true.

Unlock rule: The hero stays Neutral until the app has at least 3 completed cycles and at least one completed cycle whose start and next-start were both logged live.
State When it appears What it should say or imply
Neutral Before classification unlock, or when no reliable phase estimate should be shown. Day count can show when a start date exists, but no phase confidence should be implied.
Confident Classification is Regular and the clean logged-cycle gate is open. Exact current day and exact phase name.
Hedged Classification is Variable, or a later manual date makes the active window less trustworthy. Use estimate language such as ~Day 14 and probably Follicular.
Unpredictable Classification is Unpredictable and the same gate has opened. Show Menstrual on logged bleed days. Other days use an honest neutral card with no phase estimate.

4. Cycle Classification

Classification measures how consistent the user's recent cycle lengths are compared with her own recent average. It does not judge whether she has a 28-day cycle.

cycle length = next period start - previous period start mean = average of the selected cycle lengths deviation = absolute value of cycle length - mean MAD = average of all deviations
Data ruleExpected behavior
Minimum sampleDo not classify until 3 completed cycles exist, which requires 4 period start dates.
Growing windowUse all completed cycles when there are 3, 4, or 5.
Rolling windowOnce 6 or more cycles exist, use only the 6 most recent completed cycles.
Manual and logged startsBoth count for the math. Display confidence is handled separately by the hero-card rules.

5. Phase Ranges

Once the hero is allowed to show phase behavior, Ritu computes phases from two values: P, the period duration, and C, the cycle length.

Menstrual = day 1 to day P Follicular = day P+1 to day C-17 Ovulatory = day C-16 to day C-14 Luteal = day C-13 to day C
ClassificationValue used for CDisplay
RegularPersonal average cycle length.Exact day and phase.
VariableMidpoint between shortest and longest cycle in the active window, rounded half up.Same formula, but displayed as an estimate.
UnpredictableNo value used.No phase math outside observed menstrual days.

Short-cycle fallback

Sometimes the cycle is too short to fit every phase cleanly. The app should preserve Luteal first, compress Ovulatory next, and drop Follicular when there is no room.

TierConditionBehavior

C - IrregularC - P < 15 or C <= PShow no phase strip for this cycle. Use neutral copy that says the cycle is unusually short.

6. Validation Checklist

Use this list to compare the app behavior against the consolidated spec. Each item should be testable in unit tests, widget tests, or fixture-driven manual QA.

  • 1Logging flow on a day creates or continues a period episode and marks the period start as Logged when it starts a new episode.
  • 2One explicit None day after flow does not close the period if flow resumes before closure is finalized.
  • 3Two consecutive explicit None days close the period, while skipped days do not count as None.
  • 4An open period cannot extend beyond day 10 without being closed by the safety cap.
  • 5When the user goes silent after Day 1, the hero advances from assumed period duration and shows the Home nudge after the assumed boundary passes.
  • 6The Home nudge lets the user confirm the actual period end date and uses that confirmed date for future classification math.
  • 7The hero stays Neutral until both 3 completed cycles exist and at least one logged-to-logged cycle exists.
  • 8Manual dates count toward classification math but reduce display confidence until a clean live cycle exists.
  • 9Classification uses MAD over 3-5 available cycles, then the most recent 6 cycles once the user has 6 or more.
  • 10Regular, Variable, and Unpredictable thresholds are 0-4, 5-9, and 10+ MAD days respectively.
  • 11Regular phase ranges use the user's personal average cycle length, not a hardcoded 28-day cycle.
  • 12Variable phase ranges use the midpoint of shortest and longest recent cycles, rounded half up, and display hedged language.
  • 13Unpredictable users see Menstrual on logged bleed days and an honest no-estimate card on other days.
  • 14Short-cycle Tier B removes Follicular rather than rendering a tiny or overlapping segment.
  • 15Short-cycle Tier C and longer-than-usual classified cycles drop phase estimates rather than implying false precision.
